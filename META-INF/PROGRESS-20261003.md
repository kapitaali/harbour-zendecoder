### Architecture decision (daemon vs static link)
- v0.1 decodes via system `org.amberapi.zxing` D-Bus daemon (text only,
  `format` reserved empty). Rationale: SDK target ships zxing-cpp **2.0.0**
  headers while the 5.2 device runs **3.0.2** (`libZXing.so.3`) — linking
  the system lib would bake the wrong soname; vendored static zxing-cpp
  (PLAN.md plan B) is the correct full-format path and lands next.
- Daemon introspection: only `decodeFromDescriptor` + `quit` (strings on
  `/usr/libexec/zxing-daemon`); wraps `ZXing::ReadBarcode` + `ReaderOptions`.
  No format-returning method exists.

### Session 9 (2026-10-03): static decode wired in (vendored zxing-cpp v3.0.2)
- New `src/staticdecoder.{h,cpp}`: `StaticDecoder : QObject` moved to its
  own `QThread`; `submit(image)` writes the image + queued no-arg
  `decode()` invocation (image rides the member — no metatype in queued
  args); grayscale (`Format_Grayscale8`) → `ImageView(..., Lum, stride)` →
  `ReadBarcode` with `BarcodeFormat::All` + tryHarder + tryDownscale; one
  `resultReady(found, text, format, ms)` per submit (try/catch around
  zxing, always emitted — Decoder's busy flag hangs on it).
- `decoder.{h,cpp}` now hybrid: static first, D-Bus daemon as fallback on
  static miss (`static miss -> service fallback` vs `static decoded` /
  `service decoded` log lines tell which path answered). Busy spans the
  whole chain; `m_oneShot` is a parameter through
  `loadFile(path, deleteAfter, oneShot)` / `submitFrame(image, oneShot)`
  and stored only after busy is acquired; every one-shot failure path
  (busy drop, read fail, memfd/write fail, service unavailable, call
  error, double miss) emits `notFound()`. ARGB32 packing deferred to the
  fallback (`packPixels()`), so the static path never touches pixels on
  the UI thread. Dtor order: `delete m_static` (quit+wait) →
  `removePostedEvents(this, 0)` → close fd.
- `.pro`: dropped `concurrent` from `QT +=` (qfutureinterface.h vs Qt 5.6
  breaks under C++20 anyway; no QThreadPool — the worker-thread pattern
  covers it), SOURCES/HEADERS += staticdecoder. RPM Requires still show no
  libQt5Concurrent.
- Build aarch64 GREEN, Harbour validator PASSED. Stale comments updated
  (decoder.h/.cpp top, ScannerPage.qml header).
- Do-not-re-derive: a parented QObject cannot be `moveToThread()`'d —
